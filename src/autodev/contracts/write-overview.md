# WriteOverview（概要 PR のタイトルと本文）の指示書

概要 PR のタイトルと本文を書いて返す。PR は driver が作り、タイトルと本文を載せる。このステージは、
計画が反映されたとき（初回と再計画のたび）と、ランが終わるときに走る。

## 入力

| 名前 | 中身 |
| --- | --- |
| `<worktree>` | いまいるディレクトリ。概要ブランチの worktree。ここから出ない |
| `<ブリーフ>` | 起動時の指示と、リポジトリごとの設定 |
| `<コードマップ>` | コードベースの入口 |
| `<設計>` | いまの設計ファイル |
| `<タスクの一覧>` | 全タスクの id・件名・状態・PR 番号 |
| `<タスク PR の本文>` | 積んだタスクの PR の本文の置き場。まだ 1 本も積んでいなければ空 |
| `<概要ブランチ>` | 概要 PR のブランチ。ランの base から切り、空のコミットを 1 つ載せただけなので、中身はランの base と同じ |
| `<スタックの一番上>` | いま一番上に積んであるブランチ。まだ 1 本も積んでいなければ概要ブランチ |
| `<概要 PR の雛形>` | 本文の雛形（`templates/overview-pr-body.md`） |

## すること

1. `<ブリーフ>`・`<設計>`・`<タスクの一覧>` を読む。積んだタスクがあれば、`git diff <概要ブランチ>..<スタックの一番上>`・
   `git log --oneline <概要ブランチ>..<スタックの一番上>` と `<タスク PR の本文>` を読む。比べる元にランの base の
   名前（`main` など）を使わない。手元のそのブランチは origin より古いことがあり、このスタックに無いコミットが
   混ざる
2. リポジトリの PR テンプレートを探す。GitHub は `.github/`・`docs/`・リポジトリ直下を、大文字と小文字を
   区別せずに探す（`find . -maxdepth 3 -not -path './.git/*' -iname 'pull_request_template*'`）。
   `.github/PULL_REQUEST_TEMPLATE/` の下に複数あれば、この作業に合うものを 1 つ選ぶ
3. `<概要 PR の雛形>` から本文を組み、タイトルを付けて返す（下の「本文の形」「タイトル」）

いまリポジトリに見えているものだけを書く。

- まだ何も積んでいない（計画が反映された直後）: 上の区画は予定として書く。確かめる手順も予定の操作として書く
- 積んだタスクがある: 実際に変わったことを書く。タスク PR の本文の「どう確かめたか」を、確かめる手順の材料にする

## 本文の形

本文は、先頭の引用（stacked PR の案内）に続く 2 つの区画に分かれる。

| 区画 | 役目 | 形を決めるもの |
| --- | --- | --- |
| 上: 概要 | ラン全体で何が変わり、どう確かめればよいかを、初めて見るレビュアーに伝える | リポジトリの PR テンプレート。無ければ雛形の上の区画（「何が変わるか」「どう確かめるか」） |
| 下: 記録 | 進み具合と、ランの中で決めたことを残す | 雛形の `<!-- autodev:waiting -->` の行から末尾までを、そのまま使う |

- 先頭の引用は消さない。draft が上のタスク PR のマージを止めていることを、読み手はここで知る
- 上の区画は畳まずに、引用のすぐ後に置く。上の区画の「（…）」の行は、書いた中身で置き換える
- 下の区画は、PR テンプレートに合わせて動かしたり、節を足したり削ったりしない。details タグの折りたたみも雛形のまま残す。
  レビュアーが最初に読むのは上の区画なので、autodev の記録は畳んで後ろに置いてある

### PR テンプレートがあるとき

上の区画を、雛形の 2 節ではなくテンプレートの節で書く。

- 見出しと並びは、テンプレートのまま全部残す。書くことが無い節も消さず、なぜ無いかを 1 行書く
- 雛形の 2 節に書くはずだったこと（何が変わるか・どう確かめるか）は、テンプレートの近い節に入れる。
  当てはまる節が無ければ、テンプレートの節の後ろに節を足す
- テンプレートにある説明用の HTML コメント（`<!-- ここに概要を書く -->` など）は消す。`<!-- autodev:… -->` の
  マーカーは消さない
- テンプレートにある自己申告のチェック項目（「セルフレビューした」「テストを足した」など）は、ランの中で実際に
  確かめたものにだけ印を付ける。確かめていないものは印を付けずに残す

### マーカー

下の区画には、driver が状態から埋める行がある。次の行は、1 行に単独で、雛形のとおりの文字のまま残す。
中身は driver が書き出すたびに埋め直すので、タスクの数・状態・PR 番号・判断ログをここで書かない
（書くと、後から積んだタスクが反映されずに古いまま残る）。

| 行 | driver が埋めるもの |
| --- | --- |
| `<!-- autodev:tasks -->` | タスクの一覧（件名・状態・PR） |
| `<!-- autodev:waiting -->` | 回答を待っていることを、見出しごと。待ちが無ければ空にする |
| `<!-- autodev:decisions -->` | 判断ログ（計画が決めたこと・回答と、その出どころ） |
| `<!-- autodev:deferrals -->` | スコープの外にしたこと |
| `<!-- autodev:instruction -->` | 起動時の指示の原文 |
| `<!-- autodev:signature -->` | ラン名と更新した日時 |

マーカーを文の中やインラインコードに書かない。1 行に単独で置いた行だけが埋まる。

## 上の区画に書くこと

読むのは、この作業を初めて見る人間のレビュアーである。手元にあるのは PR の本文・差分・リポジトリだけで、
起動時の指示（下の区画に原文が載る）のほかは見えない。

- 指示や受入条件を番号で指さず、中身を書く。autodev の中だけで通じる語（ステージの名前・指摘の id など）を使わない
- 割り方の意図（なぜこの単位で PR を分けたか）を書く。`<設計>` と `<タスクの一覧>` から読み取る
- 作業の経緯は書かない。今どうなっているかだけを書く

## タイトル

ラン全体で何が変わるかを、日本語の 1 行で書く（80 字まで）。指示の文を写さず、レビュアーが PR の一覧で
見分けられる言葉にする。driver が頭に `[autodev] ` を付けるので、自分では付けない。

## 書いてよいもの

何も書かない。本文は結果で返す。ファイルに書いても driver は読まない。

## 返すもの

終わりに結果を 1 回だけ返す。返し方と形は、システムの決まりと出力スキーマに従う（外れると
差し戻されるので、言い直して合わせる）。

- `title`: 概要 PR のタイトル（上の「タイトル」）
- `body`: 概要 PR の本文（Markdown）。マーカーの行を含めたまま返す

## してはいけないこと

- コードを書き換える・commit する
- `git push` と `gh` を叩く。PR を作るのも本文を載せるのも driver だけで、エージェントが触ると積んだ PR が壊れる
- 作業の途中で driver のコマンドを叩く。次のステージを自分で呼ぶ
