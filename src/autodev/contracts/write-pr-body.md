# WritePrBody（タスク PR の本文）の指示書

このタスクの PR に載せる本文を書いて返す。PR は driver が作る。stacked PR の案内と概要 PR へのリンクは、
driver が本文の上に足す（`templates/task-pr-body.md`）ので、ここでは書かない。

## 入力

| 名前 | 中身 |
| --- | --- |
| `<worktree>` | いまいるディレクトリ。このタスクのブランチの worktree。ここから出ない |
| `<基準のコミット>` | このタスクのブランチを切った所。`git diff <基準のコミット>..HEAD` がこの PR の差分 |
| `<タスク>` | このタスクの件名・受入条件・DoD・範囲 |
| `<決めたこと>` | これまでの回答。出どころ（ユーザーかラン統括か）が付いている |
| `<指摘>` | このタスクの指摘の台帳。全件の状態とコメント |
| `<これまでの結果>` | このタスクで走ったステージの結果の JSON の置き場 |

## すること

1. `git diff <基準のコミット>..HEAD` と `git log --oneline <基準のコミット>..HEAD` を読む
2. `<タスク>`・`<決めたこと>`・`<指摘>`・`<これまでの結果>` の `notes` を読み、決めたことと、
   直さないと決めた指摘（`rejected`）を拾う
3. 本文を書いて返す

## 本文に書くこと

読むのは、この差分を初めて見る人間のレビュアーである。手元にあるのは PR の本文・差分・リポジトリだけで、
起動時の指示・設計ファイル・レビューの記録・ステージの結果は見えない。

- 何が変わるか。挙動の変化を「操作 X で A だったのが B になる」の形で 1〜3 行
- 読むときに気を付けること。当てはまるものだけ書く
  - 判断が分かれうる箇所と、選ばなかった案（`path:行` を添える）
  - 差分の外に影響が及ぶ箇所（呼び出し元・設定・互換性）
  - テストが見ていない挙動
- どう確かめたか。流したコマンドと、テストが何を確かめているか
- 直さないと決めた指摘と、その理由。無ければ省く

本文の中の参照は、手元にあるものだけで引けるようにする。指示や受入条件を番号で指さず、決まっている
中身を書く。autodev の中だけで通じる語（ステージの名前・指摘の id・`must-fix` など）を使わない。
書き終えたら、固有名詞・番号・略語を 1 つずつ拾い、本文・差分・リポジトリのどこで意味が分かるかを
確かめる。答えられないものは中身に書き換える。

## 本文に書かないこと

- 差分をそのまま言い直した説明。コードを読めば分かることは書かない
- 作業の経緯（「まず〜を試し、次に〜にした」）。今どうなっているかだけを書く
- 中身の無い前置きと締め
- stacked PR の案内と読む順（driver が足す）

## 書いてよいもの

何も書かない。本文は結果で返す。ファイルに書いても driver は読まない。

## 返すもの

終わりに結果を 1 回だけ返す。返し方と形は、システムの決まりと出力スキーマに従う（外れると
差し戻されるので、言い直して合わせる）。

- `body`: PR の本文（Markdown）

## してはいけないこと

- コードを書き換える・commit する
- `git push` と `gh` を叩く。PR を作るのも本文を載せるのも driver だけで、エージェントが触ると積んだ PR が壊れる
- 作業の途中で driver のコマンドを叩く。次のステージを自分で呼ぶ
