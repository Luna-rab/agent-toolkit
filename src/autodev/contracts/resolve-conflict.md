# ResolveConflict（衝突を解く）の指示書

2 つの側の変更がぶつかったファイルを、そのファイルの中で解く。解けるのは、両側の変更をどちらも残せる
衝突だけである。両方は残せないと判断したら、解かずにそう返す。

このステージは 2 つの所で走る。

| 走る所 | いまの worktree | 両側 |
| --- | --- | --- |
| git 管理タスク（積むとき） | タスクのブランチをスタックの一番上へ rebase する途中で止まっている。衝突したファイルに衝突の印（`<<<<<<<`・`=======`・`>>>>>>>`）がある | スタックの一番上と、積もうとしているタスクのブランチ |
| 実装タスク（統合に失敗したタスクを引き継ぐ差し込んだタスク） | rebase の途中ではない。スタックの一番上から切ったブランチで、衝突の印は無い | worktree（スタックの一番上）と、`<引き継ぎ元>` のブランチ |

解いた後、driver が両側の変更を残したかを行の単位で確かめる。その後に流す検証コマンドは、走る所で違う。

- git 管理タスク: 統合検査で軽い検査と回帰テストを流す（タスクのテストは流さない）
- 差し込んだ実装タスク: 後続の Gate でタスクのテストと軽い検査を流す

片方の変更を落としてもテストが拾わないことがあるので、テストが通るだけでは足りない。

## 入力

| 名前 | 中身 |
| --- | --- |
| `<worktree>` | いまいるディレクトリ。ここから出ない |
| `<衝突したファイル>` | 衝突したファイルの一覧。書けるのはこれだけ。実装タスクでは、引き継ぎ元が積むときに衝突したファイル |
| `<引き継ぎ元>` | 実装タスクで走るときだけ。引き継ぎ元のタスクの id とブランチ。git 管理タスクでは空 |
| `<タスク>` | 統合しているタスクの件名・受入条件・範囲 |
| `<ブリーフ>` | 起動時の指示と、リポジトリごとの設定 |

## すること

1. 両側が、`<衝突したファイル>` の各ファイルで何を足し、何を消したかを読む
   - git 管理タスク: `git status` と `git diff` で衝突の印を見る
   - 実装タスク: `<引き継ぎ元>` のブランチを B として、`git diff HEAD...B -- ファイル` で、引き継ぎ元が
     そのファイルに何をしたかを見る
2. `git log` で、両側のコミットの意図を確かめてよい
3. 両側が足した行をどちらも残し、どちらも消していない行を消さないように、ファイルを書き直す。
   片方だけが消した行は戻さない。衝突の印は残さない
4. 両方を残すと意味が壊れる（同じ関数を別々の形に書き換えた・同じ値を別々に変えた）なら、解かずに
   `report` を `integration-failed` にして返す
5. 実装タスクでは、解いたら commit する（rebase の途中ではないので、続きを driver がすることは無い）。
   git 管理タスクでは commit しない（下の「してはいけないこと」）

例: 同じテストのファイルの末尾に、両側が別々のテストを足した → 両方のテストを残す。同じ関数の返り値を、
両側が別の型に変えた → 両方は残せない。

## 書いてよいもの

`<衝突したファイル>` だけ。それ以外への書き込みはフックが止める。

## 返すもの

終わりに結果を 1 回だけ返す。返し方と形は、システムの決まりと出力スキーマに従う（外れると
差し戻されるので、言い直して合わせる）。

- `report`: 両方は残せないときだけ `integration-failed`、解けたら `null`
- `reportReason`: 両方は残せない理由。どのファイルの、どの変更とどの変更がぶつかるか。解けたら `null`
- `resolved`: 解いたファイル。`path` はファイル、`how` は両側の何をどう残したか

## してはいけないこと

- git 管理タスクで、`git add`・`git commit`・`git rebase --continue`・`git rebase --abort` を叩く。
  rebase の続きは driver がする
- `<衝突したファイル>` の外を書き換える
- `git push` と `gh` を叩く。PR・リモートのブランチ・スタックを触るのは driver だけで、エージェントが触ると積んだ PR が壊れる
- 履歴を書き換える（`git rebase`・`git reset --hard`・`git commit --amend`）。git 管理タスクの rebase を
  動かすのは driver だけ
- 作業の途中で driver のコマンドを叩く。次のステージを自分で呼ぶ
