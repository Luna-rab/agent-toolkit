# Replan（再計画）の指示書

確定した設計とタスクの一覧を、再計画の理由に合わせて書き直し、提案として返す。コードは書かない。
返した提案は、設計レビューを通ってから反映される。

## 入力

| 名前 | 中身 |
| --- | --- |
| `<worktree>` | いまいるディレクトリ（概要ブランチの worktree）。ランの base のコードしか無いので、コードは `<コードの置き場>` で読む |
| `<コードの置き場>` | スタックの一番上を固定した、読むためだけの worktree。積んだタスクの変更が入っている |
| `<ブリーフ>` | 起動時の指示と、リポジトリごとの設定 |
| `<コードマップ>` | コードベースの入口。ランの初めに書いたもので、積んだタスクの変更は載っていない |
| `<設計>` | いまの設計ファイル |
| `<設計の置き場>` | 設計ファイルの過去の版（`v1.md`・`v2.md` …） |
| `<再計画の理由>` | ラン統括が書いた理由と、きっかけのエスカレーションの調べる先 |
| `<タスクの一覧>` | 全タスクの id・状態（積んだ・走っている・未着手・回答待ち・止めた など）・中身・依存・未解決の指摘 |
| `<決めたこと>` | これまでの回答。出どころ（ユーザーかラン統括か）が付いている |
| `<ランディレクトリ>` | 調べる先のパスの起点 |
| `<autodev>` | ask を叩く入口（`autodev` コマンドの絶対パス） |

## すること

1. `<再計画の理由>` を読み、調べる先（`<ランディレクトリ>` からのパス）をたどって、何が起きたかを確かめる。
   理由は主張として扱い、実物（結果の JSON・ログ・コード）で確かめる
2. `<設計>` と `<タスクの一覧>` を読み、`<コードの置き場>` でいまのコードを読む
3. 設計ファイルとタスクを書き直す。書き方は [_proposal.md](_proposal.md) にある
4. 受入条件が一意に定まらなければ、推測で埋めずに聞く（下の「聞くとき」）
5. 提案を返す

## 書き直してよい範囲

すべてのタスクを書き直してよい。走っているタスクも、積んだタスクも含む。

- `tasks` には、足すタスクと、中身を変えるタスクだけを書く。書かなかったタスクのうち終わっていない
  ものは、今の中身のまま残る
- 止めるタスクは `stop` に書く。未着手のタスクを要らなくするときも `stop` に書く
- 積んだタスクの中身は変えない。要らないなら `discard` に書き、再利用できない理由を `design` に書く。
  積んだタスクは再利用を先に考える（破棄すると、その上に積んだタスクの PR も作り直しになる）
- 止めた・引き継がれた・破棄したタスクは書かない。依存先にもしない（積まれることが無い）
- 止めるタスクに未解決の指摘が残っていて、その中身を引き継ぐタスクがあるなら、`carry` で移す。
  移さない指摘は、タスクと一緒に消える

## 聞くとき

受入条件が一意に定まらないときは、1 つのターンで ask だけを 1 回呼ぶ。質問が複数あれば、ターンを分けて呼ぶ。

```bash
<autodev> ask --question "キャッシュの無効化は、書き込みのたびか、TTL だけか。再計画の理由はどちらとも読める"
```

- 呼ぶとステージはそこで止まり、回答が届くと同じ呼び出しから続く。コマンドは回答を出力する
- ほかのツールと同じターンで呼ぶと止まれず、ask は失敗する
- 質問は「どちらに解釈するか」を選択肢の形で書く。1 回の ask に 1 つの質問だけを書く

## 書いてよいもの

何も書かない。`<worktree>` も `<コードの置き場>` も読むだけで、書き込みはフックが止める。

## 返すもの

終わりに結果を 1 回だけ返す。返し方と形は、システムの決まりと出力スキーマに従う（外れると
差し戻されるので、言い直して合わせる）。

- `design`・`tasks`・`quickChecks`・`regressionTests`・`stop`・`discard`・`carry`・`decisions`・`deferrals`: [_proposal.md](_proposal.md) のとおり。
  `design` は書き直した後の全文を返す。`quickChecks`・`regressionTests` はラン共通の検査を全部書く（返した一覧で置き換わる）

## してはいけないこと

- コードを書き換える・commit する
- `git push` と `gh` を叩く。PR を作るのも積むのも、閉じるのも driver だけで、エージェントが触ると積んだ PR が壊れる
- 作業の途中で、ask のほかに driver のコマンドを叩く。伝えることは結果に書く
- 次のステージを自分で呼ぶ
