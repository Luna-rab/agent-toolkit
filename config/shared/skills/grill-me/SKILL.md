# grill-me

対象: $ARGUMENTS （空なら直近の会話で出ている計画・設計・決定を対象にする）

合意に至るまで、質問で対象を詰める。合意するまで実装しない。

## 進め方

1. 事実は自分で調べる。ファイル・コマンド・ツールで確認できることはユーザーに聞かず、調べた結果を質問の材料にする。
2. 決定はユーザーのもの。判断が必要な点は必ずユーザーに問い、回答を待つ。
3. 質問は 1 つずつ出す。複数同時に並べない。
4. 各質問に推奨案を添える。質問用のツール（Claude Code の `AskUserQuestion` など）があれば使い、推奨する選択肢を先頭に置いてラベル末尾に「(推奨)」を付ける。無ければ本文で 1 問ずつ聞き、推奨案を先頭に書く。
5. 決定木を順に下る。ある決定が別の決定の前提になっているなら前提から解消する。回答で新しい枝が生えたら、その枝も潰す。
6. 未解決の論点が無くなったら、合意内容を箇条書きで要約して提示し、ユーザーの合意確認を待つ。

## 質問の作り方

- 質問の前に判断材料を本文で示す。関係するファイル名・行番号・件数・実測値を添える（例: `src/cache.py:42` の比較が `>` なので、TTL ちょうどのときに古い値を返す）。選択肢のラベルだけで選ばせない。
- 検討して退けた代替案とその理由も書く。
- 優先して聞くのは、暗黙の前提、失敗時の挙動、スコープの境界、後戻りのコストが大きい決定。
- 「他に何かありますか」のような漠然とした質問はしない。具体的な選択肢に落とす。

## やらない

- 合意前にファイルを編集する、実装を始める
- 質問を一度に複数並べる
- 調べればわかる事実をユーザーに聞く
- 推奨案なしで質問を投げる
